# MOTION AI · 운동 정보 공유

기존 MOTION AI 사이트에 게시글 작성·목록·상세·운동 종류 필터를 추가한 수업용 프로젝트입니다. 게시글은 Python Flask 서버와 SQLite에 저장되며, 같은 서버에 접속한 브라우저들이 같은 글을 봅니다.

## 현재 구현 범위

- 닉네임·제목·운동 종류·본문으로 작성
- 최신순 목록, 12개 단위 페이지 이동
- 전체 / 스쿼트 / 푸시업 / 플랭크 / 기타 필터
- 고유 주소로 상세 조회 및 새로고침
- 서버 재시작 후에도 게시글 유지
- 프런트·서버 입력 검증, 오류 안내, 등록 실패 시 입력 보존
- 연속 클릭 차단, 동일 요청 재시도의 중복 저장 방지
- 입력을 문자 그대로 표시, 매개변수 DB 쿼리 사용
- 모바일 화면 대응

로그인·수정·삭제·댓글·좋아요·운동 기록 첨부는 이 버전에 포함하지 않습니다. 닉네임은 본인 인증이 아니며 누구나 동일 닉네임을 사용할 수 있습니다. 자동 실시간 갱신은 없으므로 다른 기기에서 작성한 글은 목록의 새로고침 버튼으로 확인합니다.

## 1. 이 PC에서 실행

이미 제공된 폴더에 `.venv`가 준비되어 있다면 `start.cmd`를 더블클릭합니다. 검증 중 실행해 둔 서버가 이미 8000번을 사용하면 새 서버를 중복 실행하지 않습니다.

ZIP을 새로 풀었거나 다른 PC라면:

1. Python 3.10 이상을 준비합니다.
2. `setup.cmd`를 더블클릭합니다. 최초 한 번 패키지 설치에 인터넷이 필요합니다.
3. 설치 완료 후 `start.cmd`를 더블클릭합니다.
4. 브라우저에서 `http://127.0.0.1:8000/#community`를 엽니다.
5. 종료는 서버 창에서 Ctrl+C를 누릅니다. 서버 창을 닫거나 PC를 끄면 다른 기기의 접속도 중단됩니다.

PowerShell에서 직접 실행할 수도 있습니다. 프로젝트 폴더에서:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe server.py
```

HTML 파일을 더블클릭해 열면 게시글 API가 연결되지 않습니다. 반드시 서버 주소로 접속합니다. Waitress를 사용하며 Flask 디버거는 켜지 않습니다.

## 2. 같은 Wi-Fi의 휴대폰·다른 PC에서 접속

1. 서버 PC와 접속 기기를 같은 Wi-Fi에 연결합니다.
2. PC에서 서버를 실행합니다. 기본 설정은 `0.0.0.0:8000`입니다. 0.0.0.0은 접속용 주소가 아닙니다.
3. PC에서 `ipconfig`를 실행하고 **Wi-Fi 어댑터의 IPv4 주소**를 확인합니다. VMware·VPN 주소와 구분합니다.
4. 다른 기기의 브라우저에 `http://PC의IPv4주소:8000/#community`를 입력합니다. 휴대폰에서 localhost나 127.0.0.1을 입력하면 PC에 연결되지 않습니다.
5. PC에서 글을 작성하고 휴대폰의 새로고침 버튼을 눌러 같은 글이 보이는지 확인합니다.

작업 당시 확인된 Wi-Fi 주소는 `172.18.141.203`이므로 접속 후보는 `http://172.18.141.203:8000/#community`입니다. Wi-Fi 재연결 시 IP가 달라질 수 있습니다.

### 방화벽 상태와 아직 필요한 확인

작업 당시 Windows 공용 네트워크 프로필은 인바운드 연결 차단 상태였습니다. 같은 Wi-Fi 대역에 한정해 이 프로젝트 Python 실행 파일의 TCP 8000 인바운드를 허용하는 규칙은 자동 승인 검토에서 거절되어 추가하지 않았습니다. 해당 설정은 사용자의 명시적 승인과 Windows 관리자 권한이 필요할 수 있습니다. 방화벽 전체를 끄거나 공유기 포트 포워딩을 할 필요는 없습니다.

서버의 로컬 접속과 PC 자신의 Wi-Fi 주소 접속은 검증했지만, 별도 휴대폰/PC에서의 접속은 아직 검증하지 않았습니다. 방화벽 허용 후에도 학교·공공 Wi-Fi의 기기 간 통신 차단, VPN 또는 네트워크 정책 때문에 연결이 안 될 수 있습니다. 이때는 기기 간 통신을 허용하는 개인 공유기에서 확인합니다.

## 3. 저장 위치와 백업

게시글 DB는 기본적으로 `instance/community.sqlite3`에 자동 생성됩니다. 파일이 없으면 빈 게시판을 만듭니다. 서버를 다시 실행해도 기존 DB를 초기화하지 않습니다.

- 프로그램 코드: 팀 저장소에 올립니다.
- `.venv`, `instance`와 DB 파일: `.gitignore`로 제외했습니다.
- 백업: 서버를 종료한 뒤 `instance` 폴더를 복사합니다. 실행 중 DB 파일 하나만 복사하지 않습니다.
- 복원: 서버 종료 상태에서 백업한 `instance` 폴더를 복원합니다.
- 사용자 삭제 기능은 제공하지 않습니다. 테스트는 실제 게시판과 별도 DB에서 진행합니다.

기존 운동 기록은 여전히 브라우저의 localStorage에 있습니다. Netlify 주소, localhost 주소, LAN IP 주소는 서로 다른 저장소이므로 Netlify에서 쌓은 운동 이력이 이 주소에 자동으로 보이지 않습니다. 게시글은 서버 DB에 저장되므로 같은 서버를 바라보는 주소 사이에서 공유됩니다.

또한 휴대폰의 일반 HTTP LAN 주소에서는 브라우저 보안 정책으로 기존 AI Tracker 카메라 기능이 제한될 수 있습니다. 이번 LAN 검증 대상은 게시판이며, 카메라 측정은 기존 HTTPS 사이트 또는 해당 PC의 localhost 환경에서 별도로 확인해야 합니다.

## 4. 데이터 흐름과 파일

```text
브라우저 community.js
   → community-api.js의 /api/posts 요청
   → app.py의 입력 검사 / 조회 처리
   → post_storage.py
   → instance/community.sqlite3
```

| 파일 | 역할 |
|---|---|
| app.py | Flask 앱 생성, 입력 검사, API, 정적 파일 제공 |
| post_storage.py | SQLite 생성·저장·조회, 요청 중복 방지 |
| server.py | Waitress 서버 실행, 포트·주소 표시 |
| wsgi.py | 클라우드 배포용 앱 진입점 |
| static/index.html | 기존 화면 + Community 메뉴·섹션 |
| static/community.js | 작성·목록·상세·필터와 URL 상태 |
| static/community-api.js | 서버 요청과 오류 처리 |
| static/community.css | 게시판 디자인과 반응형 스타일 |
| tests/test_posts.py | DB·API 검증 |

기존 `moving2.js`, `dashboard.js`, `MainStyle.css`, `style.css`, 이미지는 원본을 복사했습니다. index.html에는 새 스타일·스크립트 로드, Community 메뉴·섹션, 게시판 레이아웃용 body 클래스 전환을 추가했습니다. 기존 소스의 출처와 사용 권한을 팀이 확인하기 전 프로젝트 전체의 라이선스를 임의로 지정하지 않았습니다.

## 5. API

| 요청 | 기능 |
|---|---|
| GET /api/health | 서버·DB 연결 상태 |
| GET /api/posts | 전체 목록 |
| GET /api/posts?exercise_type=squat&page=1&page_size=12 | 필터·페이지 목록 |
| GET /api/posts/1 | 글 상세, 없으면 404 |
| POST /api/posts | 게시글 저장 |

작성 요청은 JSON과 UUID 형식의 `Idempotency-Key` 헤더를 사용합니다. 같은 키와 내용으로 재시도하면 같은 글을 반환합니다. 새 글은 201, 이미 성공한 요청의 재시도는 200, 잘못된 입력은 400, 키를 다른 내용으로 재사용하면 409를 반환합니다.

```json
{
  "nickname": "운동하는 사람",
  "title": "오늘의 운동 팁",
  "exercise_type": "squat",
  "content": "공유할 내용을 적습니다."
}
```

앞뒤 공백을 제거한 뒤 닉네임 1~20자, 제목 1~100자, 내용 1~5000자를 검사합니다. 글자 수는 양쪽 모두 Unicode 코드 포인트 기준입니다. 날짜는 서버가 UTC로 저장하고 화면에서는 접속자의 현지 시간으로 표시합니다.

## 6. 검증

프로젝트 폴더에서:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

자동 검증은 별도 임시 DB에서 실행되며 실제 게시글을 건드리지 않습니다. 9개 테스트가 등록·다른 클라이언트 조회·앱 재생성 후 보존·필터·페이지·입력 검증·동시 저장·중복 요청·비공개 파일 차단 등을 확인합니다.

수동 시연 순서:

1. PC에서 글 한 개 작성.
2. 상세 조회 후 브라우저 새로고침.
3. 다른 종목 필터에서 제외되고 전체에서 다시 보이는지 확인.
4. 다른 기기에서 같은 서버 주소로 조회.
5. 서버 종료 후 재실행해 글이 남는지 확인.

## 7. 나중에 클라우드로 옮기기

화면과 API를 같은 서버에서 제공하는 구성을 기본으로 유지하면 상대 주소 `/api`를 그대로 사용할 수 있습니다.

- 실행: `python server.py` 또는 `waitress-serve --port=8000 wsgi:app`
- 환경 변수: `HOST`(기본 0.0.0.0), `PORT`(기본 8000), `DATABASE_PATH`(DB 파일의 절대 경로)
- SQLite를 유지하려면 재시작·재배포에도 남는 영구 디스크가 필요합니다.
- 영구 디스크가 없는 환경이라면 post_storage.py를 관리형 DB에 맞게 교체하고 데이터를 이전해야 합니다.
- 별도 Netlify 프런트엔드로 나누면 API 주소뿐 아니라 허용 출처·쓰기 요청 보호 정책도 맞춰야 합니다. 현재는 같은 출처만 지원합니다.
- 무료 플랜의 사용량·휴면·데이터 보존 조건은 배포 시점에 확인합니다.
- 공개 서비스 운영으로 넓힐 때는 인증·관리·도배 방지 정책을 추가로 검토합니다.

## 8. 팀 저장소에 반영

이 결과물은 독립 폴더입니다. 아직 팀 GitHub 저장소에 올리거나 브랜치를 생성하지 않았습니다. 팀 저장소에서 `feature/workout-sharing` 브랜치를 만들고 이 변경을 반영한 뒤 PR과 리뷰로 병합합니다. 기존 웹 프로젝트 재사용 범위와 Python 서버를 결합한 과제 구성이 인정되는지는 팀에서 확인합니다.

다른 팀원에게 구현을 맡길 필요 없이 이 폴더로 게시글 화면·서버·DB 전체를 실행할 수 있습니다. 추후 운동 기록 첨부를 구현할 때만 팀의 기록 ID·날짜·단위 형식을 맞추면 됩니다.
